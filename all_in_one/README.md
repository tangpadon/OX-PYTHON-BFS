# เอกสารอธิบายการทำงานของระบบเกม OX (All-in-One Standalone)

เอกสารนี้จัดทำขึ้นเพื่ออธิบายโครงสร้างและการทำงานของไฟล์ [`all_in_one.py`](all_in_one.py) ซึ่งเป็นโค้ดที่รวบรวมระบบเกม OX (Tic-Tac-Toe) ขนาด 3×3 ทั้งหมดไว้ในไฟล์เดียว ครบถ้วนทั้ง **แกนประมวลผล BFS Game Tree**, **อัลกอริทึม Minimax**, **ระบบแสดงผล Debug** และ **หน้าต่างกราฟิก (Tkinter GUI)** โดยไม่ต้องพึ่งพาไลบรารีภายนอก (Zero External Dependencies)

---

## 1. ภาพรวมสถาปัตยกรรมภายในไฟล์ (Code Architecture)

ภายในไฟล์ [`all_in_one.py`](all_in_one.py) ถูกจัดเรียงเป็น 5 ภาคส่วนหลักตามลำดับการทำงาน (Top-Down Execution):

```
all_in_one.py
│
├── 1. Constants & Helper Functions   # ค่าคงที่และฟังก์ชันจัดการกระดาน (Board Utilities)
├── 2. Debug                          # ฟังก์ชันจัดรูปแบบและแสดงผลข้อมูลการค้นหาของ Tree
├── 3. Game Tree Node BFS Engine      # โครงสร้าง GameNode และการสร้างต้นไม้ด้วย BFS + Minimax
├── 4. GUI Application                # ส่วนติดต่อผู้ใช้เชิงกราฟิกด้วย Tkinter (OXGameGUI)
└── 5. Main Entry Point               # จุดเริ่มต้นรันโปรแกรม (main loop)
```

---

## 2. คำอธิบายรายละเอียดแต่ละส่วน (Detailed Section Breakdown)

### ส่วนที่ 1: Constants & Helper Functions (ค่าคงที่และฟังก์ชันจัดการกระดาน)
ทำหน้าที่จัดการข้อมูลพื้นฐานของกระดานเกม 3×3 ซึ่งถูกแทนค่าด้วยสตริงความยาว 9 ตัวอักษร เช่น `'         '` (กระดานว่าง)

* `WINNING_COMBOS`: ทูเพิลเก็บดัชนีชุดเส้นชัยชนะ 8 เส้นทาง (แนวนอน 3, แนวตั้ง 3, ทะแยงมุม 2)
* `get_opponent(player)`: สลับสัญลักษณ์ผู้เล่นระหว่าง `'X'` และ `'O'`
* `swap_symbols(board)`: สลับตัวอักษร X เป็น O และ O เป็น X ทั่วทั้งกระดาน สำหรับการเทียบเคียงสถานะสมมาตร
* `place_symbol(board, position, player)`: ฟังก์ชันสร้างกระดานสถานะใหม่เมื่อมีการลงสัญลักษณ์ในช่องที่กำหนด
* `check_board_winner(board)`: ตรวจสอบสถานะกระดานว่ามีฝ่ายชนะหรือไม่ หรือเกมเสมอกระดานเต็ม (`'Draw'`)

---

### ส่วนที่ 2: Debug (ระบบบันทึกและแสดงผลการค้นหา)
ทำหน้าที่แปลงข้อมูลสถานะและกิ่งก้านของ Game Tree ให้เป็นข้อความเชิงเทคนิค (Algorithmic Debug Output) เพื่อแสดงในคอนโซล:

* `format_row(board, start_index)`: จัดรูปแบบการแสดงผลกระดานแถวละ 3 ช่องให้อ่านง่าย เช่น `X | . | O`
* `get_debug_text(tree, board, player, turn, chosen_move)`:
  * แสดงกระดานปัจจุบันในเทิร์นนั้น
  * แจกแจงกิ่งลูกที่เป็นไปได้ทั้งหมด (Child Nodes)
  * แสดงค่าประเมิน **Minimax Value** (`+1`, `0`, `-1`) และสถิติเส้นทางจบเกม (**ชนะ, แพ้, เสมอ**)
  * แสดงภาพจำลอง (Preview) ของกระดานหากเดินลงในแต่ละช่อง
  * ระบุกิ่งที่ AI ตัดสินใจเลือกเดิน (`AI เลือกเดิน: ช่อง (...)`)

---

### ส่วนที่ 3: Game Tree Node BFS Engine (แกนประมวลผลต้นไม้เกม)
หัวใจหลักของการค้นหาและการตัดสินใจของ AI ประกอบด้วย 2 คลาสหลัก:

#### 1) คลาส `GameNode` (โครงสร้างโหนดต้นไม้เกม)
เก็บข้อมูลสถานะของแต่ละโหนดใน Game Tree:
* `board`: สตริงสถานะตาราง ณ โหนดนั้น
* `player_turn`: ผู้เล่นที่มีสิทธิ์เดินในตานี้
* `move`: ดัชนีช่อง (0–8) ที่เดินมาจากโหนดแม่
* `depth`: ระดับความลึกของต้นไม้ (เทิร์นที่ 0–9)
* `children`: ลิสต์เก็บโหนดลูกที่เป็นไปได้ทั้งหมด
* `is_terminal`: บูลีนระบุว่าเป็นจุดสิ้นสุดเกมแล้วหรือไม่
* `wins_x`, `wins_o`, `draws`: สถิติจำนวนเส้นทางจบเกมที่เป็นไปได้ใต้กิ่งนี้
* `minimax_val`: ค่าประเมินกลยุทธ์ตามหลัก Minimax

#### 2) คลาส `OXBFSTree` (อัลกอริทึมสร้างและประเมินต้นไม้)
* **การสร้างต้นไม้ด้วย BFS (`_build_tree`)**:
  * ใช้ **Queue (FIFO)** ผ่าน `collections.deque`
  * เริ่มต้นที่ Root (`' ' * 9`, ตาของ X) แล้วขยายกิ่งทีละชั้น (Level-by-Level)
  * สร้างโหนดสถานะครบทุกรูปแบบที่ถูกกฎกติกา จำนวนรวม **549,946 โหนด** และมีโหนดปลายทาง (Leaves) **255,168 โหนด**
  
* **การส่งต่อค่า Minimax และนับผลลัพธ์แบบย้อนกลับ (Bottom-Up Backpropagation)**:
  * ใช้ `for node in reversed(all_nodes):` คิดย้อนจากโหนดใบ (Leaves) กลับขึ้นไปหาราก (Root)
  * **โหนดใบ (Terminal):** กำหนดค่าตามผลจริง ($X ชนะ = +1, O ชนะ = -1, เสมอ = 0$)
  * **โหนดแม่:** 
    * บวกสะสมจำนวนครั้ง ชนะ/แพ้/เสมอ จากลูกทุกกิ่ง (`node.wins_x += c.wins_x`, ...)
    * ตาของ X (Maximizer) $\rightarrow$ ดึงค่าลูกแล้วหา $\max$
    * ตาของ O (Minimizer) $\rightarrow$ ดึงค่าลูกแล้วหา $\min$

* **การประเมินและเลือกตาเดิน (`evaluate_branches`)**:
  AI ทำการเลือกตาเดินผ่านเกณฑ์การตัดสินใจ 3 ระดับ:
  1. **Direct Win/Block Check:** หากมีตาเดินที่ทำให้ชนะทันที หรือคู่แข่งจะชนะในตาถัดไป จะเดินช่องนั้นทันที
  2. **Minimax Filtering:** กรองเฉพาะกิ่งที่ให้ค่า Minimax สูงที่สุด (เพื่อการันตีความปลอดภัยตามทฤษฎีเกม)
  3. **Tie-Breaking by Score:** หากมีหลายกิ่งที่ Minimax เท่ากัน (เช่น เสมอ 0 เท่ากัน) จะเลือกกิ่งที่มีค่า `score = wins - losses` สูงที่สุด เพื่อสร้างความได้เปรียบสูงสุดหากมนุษย์เดินพลาด

### ส่วนที่ 4: GUI Application (หน้าต่างแสดงผลกราฟิก Tkinter)
คลาส `OXGameGUI` ควบคุมหน้าต่างโปรแกรม:
* **การจัดสัดส่วน Layout แบบ 48:52**:
  * ฝั่งซ้าย (48%): ตารางกระดานเกมขนาด **510 × 510 พิกเซล** ทำให้ช่องปุ่ม 9 ช่องมีสัดส่วนเป็น **สี่เหลี่ยมจัตุรัส 1:1 (160 × 160 px)** พร้อมแถบคะแนนและป้ายสถานะ
  * ฝั่งขวา (52%): คอนโซล Debug Text พร้อม Scrollbar ทั้งแนวตั้งและแนวนอน
* **ฟังก์ชันการทำงาน:**
  * `start_new_game`: รีเซ็ตสถานะกระดาน ปุ่มกด และคอนโซลเพื่อเริ่มเกมใหม่
  * `_on_cell_clicked`: รับคลิกจากผู้เล่น (X)
  * `_execute_move`: อัปเดตกระดาน เปลี่ยนสัญลักษณ์ และบันทึก Log ลงคอนโซล
  * `_ai_turn`: รันการคำนวณของ AI (O) หลังการหน่วงเวลาสั้นๆ (250 ms)
  * `_check_game_end`: ตรวจสอบผู้ชนะ ไฮไลต์ช่องที่ชนะด้วยสีเขียวอ่อน (`#C8E6C9`) และอัปเดตกระดานคะแนน

### ส่วนที่ 5: Main Entry Point (จุดเริ่มต้นทำงาน)
ตรวจสอบเงื่อนไข `__name__ == '__main__'` แล้วเปิดหน้าต่าง Tkinter เพื่อเริ่มต้นการทำงาน

```python
if __name__ == '__main__':
    root = tk.Tk()
    app = OXGameGUI(root)
    root.mainloop()
```

## 3. หลักการเลือกตาเดิน: ทำไมต้องผสาน Minimax กับสถิติ ชนะ/แพ้?

ในระบบนี้มีการผสานข้อมูล 2 ด้านเพื่อการเล่นที่ไร้จุดอ่อน:

| ข้อมูล | ความหมาย | บทบาทในอัลกอริทึม |
| :--- | :--- | :--- |
| **Minimax Value** (`+1`, `0`, `-1`) | ประเมินผลลัพธ์ภายใต้สมมติฐานว่า **"คู่แข่งเล่นดีที่สุด (Optimal Play)"** | **ตัวกรองด่านแรก (Safety First):** ป้องกันไม่ให้ AI เดินเข้าไปในเส้นทางที่สุ่มเสี่ยงต่อการแพ้ |
| **สถิติ ชนะ / แพ้ / เสมอ** | นับจำนวนเส้นทางเกมทั้งหมดใต้กิ่งนั้น ซึ่งรวมถึงตาที่คู่แข่งอาจเดินผิดพลาดด้วย | **ตัวตัดสินเมื่อคะแนนเท่ากัน (Tie-breaker):** หากทุกกิ่งการันตีเสมอเหมือนกัน AI จะเลือกกิ่งที่กดดันคู่แข่งได้มากที่สุด |
